
### 📖 LevelCraft 的转向
4 月 28 日

昨天我把计划发到了 Reddit 和 Godot 论坛上，反馈并不算正面，主流的态度大致是："不看好，但祝你好运。"

有位热心的网友还甩给我一篇就在几天前刚出炉的复盘文章——一次想用"vibe-code"方式做银河战士恶魔城类游戏的失败经历。https://forum.godotengine.org/t/post-mortem-of-my-failed-attempt-to-vibe-code-a-metroidvania-game/137567/19

今天，我刚把美术素材调好，正打算一头扎进"制造"机制的搭建时，犹豫了。

如果说 40 年的经验让我看清了自己的最大缺点，那就是：我变主意变得很快。我决定转向，先找一款规模更小的游戏来探探路。我打算认真投入 2-3 周的时间，应该足够看清楚这套工作流到底能不能跑得通。

说干就干。我翻出一款很老的游戏作为参考，立刻动手。

新项目叫 **Ricochet**，同样是带明显关卡感的动作游戏。计划完全依靠 Claude Code AI 来辅助编码。最终目标是交付：游戏本体、内置的关卡编辑器、以及一个能让玩家创建、游玩、分享关卡的完整网站。目标周期：4 周完成（给自己留点余量）。

如果这次没失败，我会再慢慢把"超级马里奥制造"那个想法捡回来。LevelCraft 到时候可以演化为支撑两款游戏关卡编辑器的后端基建。当然，我自己的主项目仍然是真正的优先级——那个不会动。但接下来这几周，我会全力扑在 Ricochet 上。

祝我好运。

结果总结：11 天，网站上线了。包括网站，游戏，关卡编辑器，0行手写代码。结果怎样大家可以看看。 Levelcraft.gg


全部开发，软件开发使用了VS Code。AI工具使用Claude Code插件（软件架构，代码），Codex插件（Sprite图像生成）。网站使用Vercel和Supabase。

游戏引擎开始使用Godot，后来根据Claude建议，改为phaser。我以前有使用Unity的经验，这两个引擎的经验为0。现在，也是0.


因为到现在为止，0行手写代码，全部代码由Claude生成。包括软件架构，到后来替换引擎的建议。替换引擎的工作，Claude建议了13个步骤，逐步进行。中间也给与测试效果的建议，根据结果又对步骤做了一定的修改。

包括Vercel和Supabase，也是上次开发我的另外一个项目，Claude为0经验的我推荐并指导我一步一步完成的。



**开发过程**

对于编码，基本一个有经验的程序员几个月能完成的工作，如果不是特别特殊的技术，一般应用的话，应该可以指导AI在几周时间内完成。

而且以前的开发流程需要业内人员向开发人员解释清楚需求，再由开发人员实施，结果拿给业内人员使用，发现问题，给开发人员解释清楚，再修改，再测试。。。。

如果业内人员能直接向AI说清需求，AI提供结果，修改。效率会大大提高。不再需要开发人员。（老码农要哭晕过去了）

有一些修改，我不太确认没有经验的是不是能准确定位。比如我的主角如果贴着墙向上跳的时候，有时候会在中间被看上去垂直的墙挡住，有时候又没问题。根据经验，我判断是大家都是正方形的碰撞盒，有时候随机误差造成了碰撞。告诉AI不让主角贴墙，反弹保持有一定的距离。包括水平也离地一点飞行，就避免了这个问题。

还有在空一格的地面，有时候主角不能落下去。告诉AI不要给主角用正方形的碰撞盒，把左右收缩几个像素，就避免了。这些都是以前开发类似游戏的经验。



因为还有其它主要项目，这11天不是全职开发这个游戏，大概用了一半的时间吧。当然是程序猿的工作时间，不是一天8小时工作制。



实际其中还耗了不少时间在美术素材的生成。比起0代码开发，即使使用了据说现在最先进的Codex，生成的图片还是避免不了手工用Photoshop编辑，裁剪对齐图片。另外在生成图片的过程中，经常会偏离美术风格，需要告诉它参考一下XXX图片再设计，才能又拉回来。

另外做场景，做地图元素效果很好，但是做有立体的多个角度的动画图片，问题很大。比如游戏中的能量瓶，本来是让它做一个绕垂直轴旋转的8帧动画的.但是8个方向总会有一两个生成错误，试了一个多小时也没能成功，最后只好改为一个发光的动画了。

另外一个手工做的动画就是传送带，需要3张图片左端，中段，右端。AI生成的3张没法拼接出来。最后用了它画的外框，自己手工画了里面移动的箭头。（结果很难看，大家容忍一下业余美术的水平）



不知道是不是我不是专业美术也没有仔细研究这个生成问题。希望有美术朋友能研究一下。最好是能有结论美术能完全靠AI，程序不行啊。。。我们可以配合一下了。



整个网站的生成，也是完全依靠AI，包括全部美术工作。扔给AI一张参考图，告诉它我希望网站长这个样子，我的网上是做XXXX的，需要XXXXX功能。就出来了。后面详细一个一个功能沟通。0代码。



我用的是Claude Max Plan。中间有一天遇到了Token消耗完了。那天是把代码从Godot迁徙到Phaser，相当于要不断阅读旧代码生成新代码，所以工作量比较大。对于一般开发强度，应该够用了。

另外几次遇到复杂一些的修改，最长的一次跑了25分钟，接近20分钟的也基本天天会有。不过中间一直有正在干什么的提示，还可以接受。给了我不少刷手机的时间。



**重要：总结**

实验下来的结果。这种规模的游戏，程序基本可以被取代了。美术还差一些，或者说有些限制需要规避。但是程序可以被替代100% 0 代码了。AI做的美术素材，暂时只能说“能用”，离精美还相去甚远。当然，再复杂的游戏，可能程序实现起来也有问题。

但是游戏一直最重要的是idea。现在有了好的idea，不会受限于缺少程序和美术，AI可以帮你快速实现了。Game By Talk Only。



另外，用时间比较多的还有关卡设计。AI可以帮助我们干活，不能帮助我们思考。AI可以加速我们实现Idea的过程，但是关键还是要有一个好Idea。
