### Phase 1 — Playtest gate

- New column `levels.last_cleared_at`. PUT (data save) clears it to
  NULL; mark-cleared sets it to a timestamp; PATCH publish refuses
  flip when NULL (`code: "playtest_required"`).
- `PlayScene` adds `publishVerify` init flag. Posts `level-cleared`
  to host on exit when set; persists across cross-page restarts.
- `EditScene` listens for `start-publish-verify`, auto-saves dirty
  level via `saveLevelToHost`, then `scene.start('PlayScene', ...)`
  from page 0.
- `PublishToggle` modal flow: prompt on stale → start verify (silent
  iframe scene change, no overlay) → on `level-cleared` auto-pop
  "Test passed ✓ Publish?" → confirm → publish. Errors render in
  modal so failed publishes don't disappear.
- Play page: same RatingWidget surface; natural play-through fires
  `level-completed` which marks the gate cleared too (creator-only).

### Phase 2 — Sprite-rendered PNG thumbnails

- New column `levels.thumbnail_url`. Storage bucket
  `level-thumbnails` (public read).
- `lib/thumbnail/render.ts` renders 720×432 PNG using real game
  sprites with the same sizing factors as `editor/drawers.ts`.
  Lazy `@napi-rs/canvas` import (so the route doesn't fail to load
  if a platform binary is missing).
- `lib/thumbnail/publish.ts` wraps render + Supabase Storage upload,
  returns cache-busted public URL.
- PATCH publish path renders + uploads + writes `thumbnail_url` in
  the same UPDATE that flips status. Render failure aborts publish
  with `code: "thumbnail_failed"`.
- `LevelThumbnail` component picks `<img src={thumbnailUrl}>` when
  present, falls back to inline SVG `LevelThumb`.
- All four card sites updated: FeaturedLevels, LatestLevels,
  /explore, profile.
- `web/supabase/seeds/05_backfill_thumbnails.ts` — one-off tsx
  script. Ran successfully against prod. All 10 seed levels now
  have PNG thumbnails.
- `serverExternalPackages: ["@napi-rs/canvas"]` in next.config so
  Vercel/Next bundler doesn't break the package's runtime native
  binding lookup.

### Phase 3 — Revision swap

- New column `levels.parent_id` referencing `levels(id)` with
  `on delete cascade`. Unique partial index ensures one fork per
  (parent, creator). CHECK forces forks to be drafts.
- `/ricochet/edit/[id]` page: when target is published & owned, it
  looks up an existing fork (idempotent via the unique index) or
  inserts a new draft copy with `parent_id` set, then redirects.
- PATCH publish: when row has `parent_id`, runs the swap path —
  copies fork's title / description / data / thumbnail_url /
  last_cleared_at into the parent row, deletes the fork, returns
  `{swappedToId}` so the client can `router.replace` to the parent's
  play page.
- Public listings (homepage, /explore) explicitly filter
  `parent_id IS NULL` (defense-in-depth).
- Profile cards expose `parentTitle` via self-join; fork cards show
  "Edit" badge + "editing live version" subtitle.

### Phase 4 — 1–5 star ratings

- New `ratings` table (composite PK on `user_id`, `level_id`).
  Denormalized `levels.rating_sum` + `rating_count` maintained by
  trigger on insert/update/delete.
- New `POST/DELETE /api/levels/[id]/rate`. Server-side gate
  (`code: "self_rate"`) blocks rating own levels;
  (`code: "not_published"`) blocks rating drafts.
- `RatingWidget` (interactive 5-star) on play page header for
  signed-in non-owners. `RatingDisplay` (compact `★ N` or
  `★ 4.3 (12)`) on every card.
- `LevelDetail.viewerRating` exposes the viewer's existing rating
  via parallel select.

### Phase 5 — /creators directory

- New RPC `all_creators()` — every profile with a published
  non-fork level + aggregate stats (level_count, total_plays,
  total_likes, rating_sum, rating_count). Sorted by total_plays
  desc.
- New page `/creators` lists all creators. Each row links to
  `/u/{username}`. Mobile/desktop responsive.
- InfoRow's "See All Creators →" link no longer 404s.
- All card sites: `by {username}` is now a `<Link>` to
  `/u/{username}`. Cards restructured to `<article>` + absolute
  overlay `<Link>` so nested links are valid HTML.
